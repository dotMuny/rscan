# Design decisions

Where two reasonable options existed, this records which was taken and what the
alternative was. The brief was: prefer the simpler one, write down the other.

---

## 1. `etherparse` + `socket2` rather than `pnet` for the SYN scan

**Chosen:** `etherparse` for packet construction and parsing, `socket2` for the
raw socket, `tokio::io::unix::AsyncFd` to make it async.

**Alternative:** `pnet`.

**Why.** `pnet` is the better-known option and its `pnet_datalink` layer can do
things this project does not need (link-layer capture, interface enumeration).
That breadth costs: `pnet` pulls in a build-time dependency on libpcap/WinPcap
for the datalink features, has a larger `unsafe` surface, and its packet types
are generated by a macro that makes compile errors hard to read.

`etherparse` is pure safe Rust with no system dependencies, its `TcpHeader`
exposes exactly the checksum helpers needed (`calc_checksum_ipv4_raw`,
`calc_checksum_ipv6_raw`), and parsing is a plain `from_slice`. Combined with
`socket2` for socket options it covers the whole requirement with less
machinery. The one thing `pnet` would have given for free — sending at the link
layer — is not wanted here: `rscan` deliberately lets the kernel build the IP
header, which is also what stops it from being able to spoof a source address.

**Consequence.** The raw sockets are `IPPROTO_TCP` without `IP_HDRINCL`, so the
kernel chooses the source address. The scanner asks the routing table what that
address will be (by connecting a UDP socket, which performs the route lookup
without sending anything) in order to compute the TCP checksum.

## 2. UDP `closed` detection through connected sockets, not an ICMP listener

**Chosen:** `connect()` the UDP socket to the target before sending. On Linux
and the BSDs the kernel then surfaces an incoming ICMP port-unreachable as
`ECONNREFUSED` on the next receive.

**Alternative:** open a raw ICMP socket alongside the UDP one and correlate
type 3 / code 3 messages back to the probe that caused them.

**Why.** The connected-socket route needs no privileges at all, which means the
UDP scan works for an unprivileged user — a large practical difference. The raw
listener would additionally have to parse the quoted IP+UDP header out of each
ICMP payload to find which probe it belonged to, and would receive every ICMP
error on the machine, not just ours.

**Cost.** ICMP codes other than "port unreachable" (admin prohibited, host
unreachable) arrive as `EACCES`/`EHOSTUNREACH` and are reported as `filtered` /
`open|filtered` without the precise code. That is a loss of detail, not of
correctness, and the reason is still reported.

---

## 3. ARP discovery through the neighbour table, not `AF_PACKET`

**Chosen:** send one datagram to the target, which makes the kernel resolve its
link-layer address, then read `/proc/net/arp` for a completed entry.

**Alternative:** build ARP frames on an `AF_PACKET` socket.

**Why.** `AF_PACKET` needs `CAP_NET_RAW` and a hand-rolled `sockaddr_ll`, which
means a meaningful block of `unsafe` for a feature that is only useful on the
local segment. The neighbour-table approach gets the same answer — "did this
address respond at layer 2?" — with no privileges and no `unsafe`.

**Cost.** Linux only, IPv4 only, and it cannot distinguish "the kernel already
had a cached entry" from "the host answered just now". The cache is authoritative
about the host having existed recently, which is what discovery is asking.

---

## 4. `scanner="nmap"` in the nmap-XML output

**Chosen:** emit `scanner="nmap"`, identify `rscan` in the `args` attribute and
in an XML comment.

**Alternative:** emit `scanner="rscan"` and accept that the output does not
validate.

**Why.** nmap's DTD declares `scanner` as an enumeration with exactly one
permitted value. The entire point of this output format is that tools which
already parse nmap XML work unchanged; a document that fails DTD validation
defeats that. masscan faces the same choice and goes the other way, which is why
some importers reject its XML.

This is the one place `rscan` presents itself as something else, it is confined
to one attribute of one optional output format, and the document says so in a
comment on the third line.

---

## 5. A hand-written DTD validator in the test suite

**Chosen:** implement the subset of DTD validation the check needs (content
models, required attributes, enumerations) in `crates/rscan-cli/tests/`.

**Alternative:** shell out to `xmllint --dtdvalid`.

**Why.** There is no pure-Rust validating XML parser on crates.io. Shelling out
to `xmllint` makes the acceptance test depend on whatever is installed on the
machine — it would skip silently wherever it is absent, and on Windows
entirely, and a test that silently skips is not a test.

The validator is about 300 lines, handles the constructs `crates/rscan-cli/data/nmap.dtd`
actually uses, and has its own tests proving it rejects the violations it is
supposed to catch (missing required attributes, bad enumerated values, wrong
child order, text in `EMPTY` elements).

**Cost.** It does not implement entities or IDs. `crates/rscan-cli/data/nmap.dtd` does not use
them; if that changes, the validator has to grow.

## 6. Count-based control windows, not time-based

**Chosen:** the AIMD controller evaluates every `window` (default 64)
network-attributable observations.

**Alternative:** evaluate every N milliseconds, with an exponentially weighted
moving average of the timeout rate.

**Why.** Count-based windows make the controller deterministic: the same
sequence of observations always produces the same sequence of decisions,
regardless of how fast they arrive. That is what lets the AIMD tests assert
exact concurrency values after an exact number of observations, instead of
asserting "it went down a bit, probably".

**Cost.** A scan that stalls completely produces no observations and therefore
no decisions. `flush()` exists to evaluate a partial window when the work queue
drains, and the governor calls it at the end of a scan.

---

## 7. A `Stream` of events, not a `Vec` of results

**Chosen:** `Scanner::run()` returns `impl Stream<Item = ScanEvent>`.

**Alternative:** `async fn scan() -> Vec<PortResult>`.

**Why.** A `/16` at the top 1000 ports is 65 million probes. A `Vec` means the
caller gets nothing for an hour and then everything at once, cannot draw an
honest progress bar, cannot stream JSONL into a pipeline, and cannot stop early
without losing the work already done. `run_to_completion()` is provided for
callers who genuinely want the `Vec`, and is implemented on top of the stream.

---

## 8. Resume state as merged port ranges

**Chosen:** store completed probes per host as merged inclusive ranges
(`[(1, 1024), (8080, 8080)]`).

**Alternative:** a set of completed `(host, protocol, port)` tuples, or a
bitmap per host.

**Why.** A finished /24 at all 65535 ports is 16 million completed probes. As
individual entries the state file would be larger than anything it is protecting.
As ranges, a fully-scanned host collapses to a single pair. A bitmap would also
be compact (8 KiB per host per protocol) but is fixed-size regardless of how few
ports were scanned, and is not human-readable in a JSON file you may need to
inspect.

**Cost.** Insertion is `O(log n)` with an occasional `Vec::insert`, rather than
`O(1)`. At checkpoint frequencies of seconds this is not measurable.

---

## 9. TOML for the probe database

**Chosen:** a TOML file with an rscan-specific escape syntax for payload bytes.

**Alternative:** nmap's `nmap-service-probes` format, or a binary format.

**Why.** The brief asked for a format of this project's own. TOML gets parsing,
comments and structural validation for free from `serde`, and `deny_unknown_fields`
means a typo in a field name is an error rather than a silently ignored line —
which is the single most common way a hand-edited probe database goes wrong.

Payloads use `\r \n \t \0 \\ \xNN` inside TOML *literal* strings, so TOML never
touches the backslashes and the decoder sees exactly what was written. The
decoder is a fuzz target.

**Cost.** nmap's probe corpus cannot be used directly. That is deliberate: it is
nmap's data, under nmap's licence.

---

## 10. Deliberate omissions

Not oversights. Each of these is absent because the project is a port scanner
and stops there.

- **No IDS evasion.** No decoys (`-D`), no source spoofing, no packet
  fragmentation, no bad checksums, no timing patterns designed to slip under
  detection thresholds. These exist in nmap with a research justification; here
  they would add nothing technically that the rest of the project does not
  already demonstrate, and they change what the repository *is*.
- **No vulnerability detection or exploitation.** Service and version
  identification is the end of the scope. There is no script engine and no
  check-for-CVE mode.
- **No idle/zombie scan.** It is a source-spoofing technique by construction.

The timing presets (`-T polite|normal|aggressive|insane`) change rate and
concurrency only. They are not nmap's `-T0`/`-T1`, which slow down specifically
to stay below detection thresholds.
